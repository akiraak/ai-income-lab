作成日: 2026-09-12。TODO「疑問に思ったことを登録し解決していく」→「台帳の役割を知りたい」。

## 1. 目的・背景

台帳（[ledger.md](../../specs/experiments/feature-discovery/ledger.md)）については、⚠ **「どう読むか」は既にあるが「何のためにあるか」が無い。**

| 既にあるもの | 何が書いてあるか | ⚠ 足りないもの |
| --- | --- | --- |
| [ledger.md](../../specs/experiments/feature-discovery/ledger.md) 本体 | 生成物としての中身（行・判定・未実施・実行の一覧） | 自分が何のためにあるかは §0 の数行だけ |
| [units.md](../../specs/experiments/feature-discovery/units.md) | 実行 → 手法 → 試行 → fold → セルの単位 | ⚠ **単位の図解であって、役割の説明ではない** |
| [rules.md](../../specs/experiments/feature-discovery/rules.md) 11・13-9・14 章 | 数え方と判定の**規約** | ⚠ **規約は「どうするか」で、「なぜ要るか」は書かない** |

読み手がつまずくのはここ。

1. 台帳は「結果の一覧」なのか、それとも**何かを決めている**のか
2. なぜ手で書き換えてはいけないのか（生成物であることに意味があるのか）
3. 基準線・門前・leak は台帳に居たり居なかったりする。何が数えられて何が数えられないのか
4. 台帳が無かったら何が起きるのか

先例は [dsr.md](../../specs/experiments/feature-discovery/dsr.md)（2026-09-12）。同じ形 ＝
**規約と生成物には手を入れず、役割だけを図と実測で説明するページ**を作る。

## 2. 対応方針

`docs/specs/experiments/feature-discovery/ledger-role.md` を新設する。

| # | 決めごと | ⚠ 理由 |
| ---: | --- | --- |
| 1 | ⚠ **解説であって規約ではない**（dsr.md・units.md と同じ宣言を置く） | 定義を 2 か所に置くと必ず食い違う。正本は rules.md と `ail/catalog.py` |
| 2 | 書くのは**役割**（何を決めているか・何を決めていないか）だけ。⚠ **行の読み方は units.md に譲る** | 3 つ目の「台帳の説明」を作らない |
| 3 | 数字は 2026-09-12 生成の台帳の【実測】として引き、⚠ **生成日を明記する** | 台帳は再生成で動く |
| 4 | ⚠ **台帳が壊れたときに何が甘くなるか**を実例（2026-09-12 の二重計上・期間の遡り）で示す | 「数え落とすと必ず甘くなる」を抽象論にしない |
| 5 | 図は Mermaid で 3〜4 枚（1 図 1 主張・12 ノード以内） | CLAUDE.md のドキュメント規約 |
