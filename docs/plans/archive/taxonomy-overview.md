# 収入体系ドキュメントの概要と読み方を作る

## 目的・背景

「人類と収入の体系」の資料が 11 ファイル・約 2,900 行まで増え、**どこから読めばよいか / どれを読まなくてよいか**が
分からなくなっている。入口の [income-taxonomy.md](../../specs/income-taxonomy.md) は体系本体（Phase 1〜5）の要約は持つが、

- 下流の検証記録（`docs/specs/experiments/` 4 件）が入口から辿れない
- 記号（L1〜L3 / P1〜P6 / 源泉 1〜9 / A1〜J4）の定義が axes.md の中にあり、他ファイルを読む前に 223 行の
  ファイルを開く必要がある
- 「今どこまで進んだか（何が成立し、何が打ち切られたか）」が DONE.md にしかなく、成果物側に無い

という 3 点で、初見・再訪のどちらでもコストが高い。

**全資料の入口となる「概要と読み方」を 1 枚作る**ことで、目的別に最短経路で辿れるようにする。

## 対応方針

新規に `docs/specs/overview.md` を作る。既存ファイルは分割・移動しない（リンクの張り替えコストが大きいため）。
入口を 2 段にする。

| 文書 | 役割 |
| --- | --- |
| `docs/specs/overview.md`（新規） | **全資料の入口**。何がどこにあるか、目的別の読む順、記号の早見表、現在地 |
| `docs/specs/income-taxonomy.md`（既存） | **体系本体の入口**。Phase 1〜5 の要約と結論 |

overview.md に載せる内容:

1. これは何か（3 行）と、体系本体との役割分担
2. 資料の全体像（図 1 枚 — 体系 → 候補 → 検証記録 → 体系へのフィードバックの循環）
3. 目的別の読む順（5 ルート。所要時間の目安つき）
4. ファイル早見表（何が書いてあるか / 読むとき / 分量）
5. 記号の早見表（これだけで全ファイルを読める状態にする）
6. 現在地（前提条件の確定値、検証 4 件の結果、残っている論点）
7. 読むときの注意（【推測】が基本であること、実測を今後取らない方針変更、日付つきで読むこと）

## 影響範囲

| ファイル | 変更 |
| --- | --- |
| `docs/specs/overview.md` | 新規作成 |
| `docs/specs/income-taxonomy.md` | 冒頭に overview.md へのリンクを追加 |
| `docs/specs/income-taxonomy/*.md`（6 件） | 冒頭の「入口:」行に overview.md を追加 |
| `docs/specs/experiments/*.md`（4 件） | 冒頭に overview.md へのリンクを追加 |
| `README.md` | 空に近いため、資料の入口を指す記述を追加 |
| `TODO.md` / `DONE.md` | タスクの移動 |

数値は既存ファイルから機械的に拾って一致させる。overview.md 側で新しい主張・新しい試算はしない。

## テスト方針

| # | テスト | 合格条件 |
| --- | --- | --- |
| 1 | 数値一致 | overview.md に書いた件数・金額が、参照元ファイルの記述と一致する（grep で照合） |
| 2 | リンク | overview.md 内の相対リンクがすべて実在するファイル・見出しを指す |
| 3 | 記号の自足性 | 記号早見表だけで catalog.md の任意の行を読める（L / P / 源泉 / ID / ⚠ /【】を網羅） |
| 4 | 図 | 1 図 1 主張、直前 1 行の主張つき、ノード 12 個以内 |
| 5 | 到達性 | 11 ファイルすべてが overview.md から 1 ホップで辿れる |
| 6 | 逆流 | 既存 11 ファイルのどれを開いても overview.md に戻れる |
