# vibeboard のタスク追加をダイアログに統一する

作成日: 2026-09-11。利用者の指示: **タスク追加ボタンを押したら画面中央にダイアログを出すような流れにできるか調べて** → 調査の結果できると回答 → **トップへの追加と、既存タスクへの子タスク追加を共通のものにする。実装を初めて**。

## 目的・背景

タスク追加（プロジェクト全体）と子タスク追加（タスク詳細）は 2026-09-11 に実装したが（[vibeboard-task-add.md](archive/vibeboard-task-add.md)）、入力フォームがそれぞれの場所にインラインで付いており、

- 実装が 2 か所に分かれている（同じ textarea・送信・下書き保持のコードが 2 組）
- 狭いサイドバーに textarea が押し込まれて窮屈
- ツリーの SSE 再描画でフォームが作り直されるため、下書き保持の仕掛けが要る

既存のモーダル（`.modal-overlay` ＋ `.modal`。409 競合ダイアログ・差分モーダルで使用実績あり）に載せた**共通のダイアログ 1 本**に置き換える。

## 対応方針

- `showAddTaskDialog(parent, onDone)` を 1 つ作る。`parent = null` がトップレベル追加、`parent = { id, text }` が子タスク追加。呼び分けは 2 つのボタンだけ
- ダイアログ: タイトル（「タスク追加」/「子タスク追加: 「親の文面」」）・textarea（1 行目 ＝ 文面、2 行目以降 ＝ メモ）・やめる / 追加する。**Esc で閉じる・外側クリックでは閉じない**（入力途中の誤クリックで文面が消えるのを避ける）。Ctrl+Enter で送信
- モーダルは body 直下なのでツリーの再描画の影響を受けない。下書きは誤って閉じた場合に備えて親 id 単位で残す（成功で消す）
- インラインフォームは両方とも撤去。ジョブの状態表示（「タスク追加の状態」欄）は今のまま残す
- サーバ・API は変更しない

## 影響範囲

- `vibeboard/src/web/app.js` — ダイアログ関数の追加、グローバルバーと詳細ペインのフォーム撤去・ボタンの付け替え
- `vibeboard/src/web/style.css` — 不要になったフォーム用スタイルの削除、モーダル内 textarea と primary ボタンの追加
- サーバ（dist）は触らないので再起動不要（src/web はディスクから配信）

## テスト方針

- `node --check` で構文検査
- API の回帰なし（サーバ無変更）を `curl /api/tasks/add-jobs` で確認
- 画面の動作（開閉・Esc・送信・下書き復元）は利用者がブラウザで確認
